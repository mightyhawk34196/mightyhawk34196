# Hey, I'm mightyhawk34196

I spend most of my time writing Python scripts that quietly keep systems running. Automation is what pulled me into coding in the first place—watching a manual process disappear into a few reliable functions still feels satisfying.

## What I work with

**Python** is my main language. I use it for everything from small CLI tools to more involved data pipelines and service glue. I prefer readable code over clever one-liners and try to keep dependencies light.

**Automation** sits at the center of a lot of what I build. Whether it’s scheduled jobs, event-driven workflows, or simple scripts that clean up after other processes, I like reducing the amount of work humans have to remember.

**Cloud** infrastructure has become part of the daily toolkit. I’ve spent time with containerized services, object storage, and managed compute. The goal is usually the same: make something run reliably without needing constant attention.

**Open source** is where I learn the most. Reading other people’s code, filing clear issues, and occasionally contributing small fixes helps me understand how real systems are put together. I value projects that document their design decisions instead of just listing features.

## How I approach things

I tend to start small. A working prototype that solves one concrete problem is more useful than a large plan that never ships. Once something works, I clean it up, add tests where they actually help, and only then think about scaling or abstraction.

I also try to keep notes on why certain choices were made. Future me (and anyone else who has to maintain the code) usually appreciates the context.
